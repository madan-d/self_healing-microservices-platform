Self-Healing AIOps Triggers

Injects faults into the backend, alerts the AIOps bot, and executes safe self-healing in real time.

Scenario 1: CrashLoopBackOff (Auto-Restart)

Forces pod exit 1. The AIOps Bot pulls previous container logs, identifies a transient crash, and executes a safe rolling restart on the deployment.

Scenario 2: Memory Leak (OOMKilled)

Allocates memory exceeding Kubernetes 256Mi container limits. Linux OOM-killer terminates container (exit 137). AIOps bot diagnoses OOM and suggests exact memory fix.

Scenario 3: Bad Release / 5xx Spike (Rollback)

Simulates broken release returning 500 errors. AIOps bot prevents restart storms and offers a one-click Human-in-the-Loop "Approve Rollback" button.
